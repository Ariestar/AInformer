## 架构评审结论（未改代码，仅报告）

主要问题，按严重度：

1. **triage 层输出无人消费**：`bin/triage.py` 写 `data/triage.json`，
   `build_site.py` / `build_feed.py` 只读 `data/items.json`。判断层是死路，
   却因缺 key 会阻塞 `publish.py`（退出码 2）。
2. **`out/_headers` 未入库**：Cloudflare Pages 的 CORS/缓存头配置，
   位于被 `.gitignore` 的 `out/` 下，且无脚本生成。新克隆后部署即丢失，
   feed.xml 的 `Access-Control-Allow-Origin: *` 会消失。
3. **`templates/briefing.md` 是死文件**：无任何脚本读取；
   `build_site.py` 在 JS 里自己拼导出格式。且模板底部引用已删除的 `rules.md`。
4. **默认 base URL 与实际部署不一致**：`build_feed.py` / `publish.py` 默认
   `https://ai-intel.pages.dev`，实际线上是 `https://ai-intel-63f.pages.dev`，
   导致 `atom:link self` 指向不存在的地址。
5. **`publish.py --project` 解析后从未使用**（部署靠 wrangler.toml 的 name）。
6. 悬空引用：`sources.toml` 提"runbook 的源审计表"；`build_feed.py` /
   `wrangler.toml` 提 `scaffold.py`（仓库内不存在）。
7. Python 版本未声明：`tomllib` 需 ≥3.11，无 `pyproject.toml` / `.python-version`。
8. 无 CI、无自动化测试；`regression/` 是人工基线（`cases.tsv` 还带 BOM）。
9. 源清单三处重复：`sources.toml`（真相）、`docs/AI情报-RSS源清单.md`（手抄 17 条 URL）。

做对的地方：bin/ 单脚本单职责、失败即停不降级、`data/`+`out/` 产物不入库、
`health.py` 的零新增检测、`.gitattributes` 统一 LF。
